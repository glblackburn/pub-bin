If you’ve ever kicked off a long `--learn -Y` run and then realized your terminal isn’t frontmost—`Ctrl+C` doesn’t help much. That’s the kind of footgun I want to fix next, but today I got honest about what’s already in the repo first.

I’ve been iterating on a small macOS script: `osx/macos_mouse_click​.py` (Python + Quartz + Rich). It does the boring magic—record a click, repeat it, or hit fixed coordinates. The code worked; the story of what was “done” did not.

𝐓𝐡𝐞 𝐭𝐡𝐢𝐧𝐠 𝐭𝐡𝐚𝐭 𝐚𝐜𝐭𝐮𝐚𝐥𝐥𝐲 𝐬𝐜𝐚𝐫𝐞𝐝 𝐦𝐞:  

▶ `-Y` means “don’t stop me for prompts”—great for scripts, awful if you fat-finger a huge `-n` or a long delay and can’t get back to Terminal in time.  
▶ I wrote that up as a real roadmap item (plan 08): stop mid-run without living in the terminal window—think stop-file or an optional global hotkey, wired into the same shutdown flag the signal path already uses.  

𝐓𝐡𝐞 𝐡𝐚𝐜𝐤 𝐈 𝐝𝐢𝐝 𝐧𝐨𝐭 𝐞𝐱𝐩𝐞𝐜𝐭 𝐭𝐨 𝐧𝐞𝐞𝐝:  

To test the legacy `--interactive` path on a machine that *has* Rich installed, you have to make `import rich` fail for one process only. So: `mktemp`, drop a tiny `rich.py` that raises `ImportError`, prepend it on `PYTHONPATH`, run the script. Gross. It works. That was the last checkbox on a nine-row manual matrix I’d been dragging around for weeks.

𝐖𝐡𝐚𝐭 𝐈 𝐰𝐫𝐨𝐭𝐞 𝐝𝐨𝐰𝐧 𝐢𝐧𝐬𝐭𝐞𝐚𝐝 𝐨𝐟 𝐦𝐨𝐫𝐞 𝐜𝐨𝐝𝐞:  

▶ Closed plan 02 for v1—Rich table UX, defects, all MT-01 through MT-09 logged, “defer” items pointed at numbered follow-on plans instead of endless “open” guilt.  
▶ Added `docs/plans/README​.md` so I can’t pretend plan 01 (behavior spec) and plan 02 (TTY UX program) are the same kind of “done”—one is “Shipped” reference, one is “Closed (v1)” delivery; the README explains that in plain English because I’ll forget why I picked two different words.  
▶ Sketched how pytest could drive the fake-Rich path later (plan 03) without lying that CI can replace “Accessibility said yes” runs.
