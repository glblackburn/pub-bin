Some bugs aren't fixable. And that's okay.

Next.js 14.0.0 and 14.1.0 have an internal bug when processing RCE PoC payloads - the error handler crashes due to a null reference, causing requests to hang indefinitely. After multiple investigation iterations (testing with React 18, React 19, different wait strategies, polling vs fixed waits), I confirmed it's a Next.js 14.x internal bug that cannot be fixed in application code. I documented it as BUG-8 (Not Fixable) and moved on.

𝐖𝐡𝐚𝐭 𝐈 𝐥𝐞𝐚𝐫𝐧𝐞𝐝:

▶ Start simple, then iterate - began with basic version switching, added features incrementally across 18 development phases (~20+ hours, 75+ commits)
▶ Some bugs are framework limitations - document and work around, don't try to fix unfixable issues
▶ Test what you think you're testing - initially version tests only ran when current version matched; had to actually switch versions to test all scenarios
▶ Framework-aware architecture - servers and utilities that adapt to context (Vite/React vs Next.js) are more flexible
▶ Polling beats fixed waits - polling-based readiness checks are more efficient than fixed wait times
▶ Root cause analysis requires iteration - complex bugs may require multiple investigation iterations (26 test runs over 2h 34m to stabilize Next.js conversion)
▶ Framework-specific tools - security scanners may be designed for specific frameworks (Next.js) and won't work with others (standalone React)
▶ DRY principles pay off - eliminated code duplication, ~72% reduction in maintenance points, ~40% complexity reduction
▶ Systematic verification matters - comprehensive verification plans help identify issues systematically

The project evolved from a simple React version switcher to a comprehensive security testing tool with framework-aware architecture, performance tracking, defect tracking (BUG-1 through BUG-9), scanner verification, and out-of-the-box setup. It now supports both Vite/React and Next.js modes, with automated testing across 7 React versions and 11 Next.js versions (9 vulnerable, 2 fixed). Phase 18 added automatic dependency installation - the project works immediately after `git clone` with zero manual setup required.

The test suite includes 28 tests with Page Object Model implementation, parallel execution support, HTML reports, and driver caching to eliminate network dependencies. Performance tracking with regression detection, historical trend analysis, and personalized time limits ensures tests stay fast and reliable.

The project serves as both a functional security testing tool and a learning resource for version management, test automation, framework-aware architecture, and performance optimization.
